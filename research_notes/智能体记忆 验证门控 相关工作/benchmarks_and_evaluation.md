# Benchmarks and evaluation designs for agent memory and cross-session continual learning (mid-2025 to Nov 2026)

Scope note: the target is a small memory layer for a coding agent, now evaluated on scripted multi-session streams in one Python repo with a simulated user, where every session passes the test suite in every condition (ceiling effect), with one project, one model, no drift. Items marked "earlier" predate mid-2025. "Preprint" means arXiv-only as far as I could verify. Venue claims that come only from secondary sources are flagged.

## 1. CL-Bench 1.0 as used in Anthropic's "The components of agent memory" (2026-11-06)

### Takeaway
CL-Bench 1.0 ("Continual Learning Bench") is a public benchmark from UC Berkeley, Snorkel AI and UW-Madison (arXiv preprint 2606.05661, June 2026; harness on GitHub under Apache-2.0). It has six stateful tasks, including a coding task (Codebase Adaptation: 19 SWE-bench issues over two repos, scored by hidden regression tests and step efficiency) and the Database Exploration task that Anthropic reported. Its key design is a "gain" metric: the same system's stateful reward minus its stateless reward on the same instance. The paper's headline is that naive in-context learning beats dedicated memory systems, and that accumulated state often hurts.

### Cited Findings
**Anthropic post (primary, 2026-11-06)**
- The post is an engineering report by Lance Martin, dated 2026-11-06. It defines memory as information learned from interactions or tasks and saved as readable context for later sessions. — [Anthropic](https://www.anthropic.com/research/components-of-agent-memory) (author and date come from a search-engine summary of this page, not from my own fetch)
- It describes CL-Bench 1.0 as "a benchmark that measures an agent's ability to use memory in order to tackle long-horizon tasks" and discusses only the database task. It links to continual-learning-bench.com/news/cl-bench-1-0/ and does not name the benchmark's authors. — [Anthropic, The components of agent memory](https://www.anthropic.com/research/components-of-agent-memory)
- Task format in Anthropic's runs: Claude answers questions by looking things up in a database. After each answer it is told the correct solution and may write a memory. Each question starts in a fresh session, and the only carry-over is a persistent memory directory. Runs used Claude Managed Agents. The post's running-mean chart covers 30 questions. — [Anthropic](https://www.anthropic.com/research/components-of-agent-memory)
- Mean reward, stateless baseline → with memory: Opus 5.5 0.655 → 0.838; Sonnet 5.5 0.644 → 0.833; Opus 5 0.564 → 0.828; Opus 4.7 0.383 → 0.700; Sonnet 5 0.306 → 0.610; Sonnet 4.6 0.330 → 0.364, and 0.641 with memory plus refined guidance. — [Anthropic](https://www.anthropic.com/research/components-of-agent-memory) (note: one secondary guide reports Sonnet 4.6 as "0.364 to 0.641", which conflates two conditions. [beri.net guide](https://www.beri.net/learning/anthropic-components-of-agent-memory))
- Instructing models to "record only failures" reduced the memory gain by 0.234 (Opus 5), 0.150 (Opus 4.7), and 0.020 (Sonnet 4.6). Stronger models did better when they could judge salience themselves. — [Anthropic](https://www.anthropic.com/research/components-of-agent-memory)
- Behaviour notes: Sonnet 4.6 kept "a scattering of files, each listing several untested guesses". Opus 4.7 consolidated notes and marked confirmed versus unconfirmed facts. Opus 5 "was the first of these models to close the loop" (record failure, form theory, test, turn into rule). — [Anthropic](https://www.anthropic.com/research/components-of-agent-memory)
- The post gives no run counts, variance or cost for CL-Bench. A secondary write-up says several results in the post are single runs and that Anthropic says so. — [Anthropic](https://www.anthropic.com/research/components-of-agent-memory); [DEV Community summary](https://dev.to/gabrielanhaia/anthropics-agent-memory-study-rules-on-what-to-save-cost-claude-much-of-the-gain-3089)
- Other evaluations in the same post: Pokémon Red, where Sonnet 3.7 wrote 413 memory files and earned 1 badge while Claude Fable 5 wrote 10 files and earned 4. A Stainless docs corpus (~350,000 files, ~420M tokens, 25 questions), where wiki-only scores rose from 13% to 48% over 128 "dreaming" sessions, and wiki plus search reached 61% against 53% for search alone. Harvey LAB legal briefs. In a Pokémon example, correcting a wrong note during dreaming changed the outcome; uncorrected, the run "never reaches Cerulean City". — [Anthropic](https://www.anthropic.com/research/components-of-agent-memory)

**CL-Bench itself**
- Release post "Continual Learning Bench 1.0", dated May 4, 2026, by "The Continual Learning Bench Team". — [CL-Bench news](https://continual-learning-bench.com/news/cl-bench-1-0/)
- Paper: "Continual Learning Bench: Evaluating Frontier AI Systems in Real-World Stateful Environments", arXiv 2606.05661, submitted 4 June 2026. Authors: Parth Asawa, Christopher M. Glaze, Gabriel Orlanski, Ramya Ramakrishnan, Benji Xu, Asim Biswal, Vincent Sunn Chen, Frederic Sala, Matei Zaharia, Joseph E. Gonzalez. Preprint; no venue listed. Paper licence CC BY 4.0. — [arXiv abs](https://arxiv.org/abs/2606.05661)
- Affiliations: UC Berkeley, Snorkel AI, and University of Wisconsin-Madison. — [arXiv HTML](https://arxiv.org/html/2606.05661)
- Harness: github.com/pgasawa/continual-learning-bench, Apache-2.0. Requires Python 3.13+, uv and Docker. Custom memory, retrieval, prompting or tool-use systems are added under `src/systems/`. Each task "spans multiple episodes in a shared environment". There is a public leaderboard and a results submission path. — [GitHub](https://github.com/pgasawa/continual-learning-bench); [site](https://continual-learning-bench.com/)
- Six tasks with instance counts: Blind Spectrum Monitoring (90 scans), Codebase Adaptation (19 issues), Cohort Studies (20), Database Exploration (40 questions), Exploitable Poker (120 hands), and Sales Prediction (count not captured). — [arXiv HTML](https://arxiv.org/html/2606.05661)
- **Codebase Adaptation**: 19 SWE-bench bug-fix issues, 9 from jazzband/tablib and 10 from jd/tenacity, run in blocked order, so the repository switches mid-stream. The latent structure to learn is where core logic lives, which test commands work, and maintainer conventions. Each issue runs in a fresh Docker container at its base commit, and the patch is checked against hidden regression tests. Reward is step efficiency, r = 1 − (steps_to_solve − 1)/max_steps with max_steps = 40; unsolved issues score 0. — [arXiv HTML](https://arxiv.org/html/2606.05661)
- **Database Exploration**: questions about an obfuscated SQLite database of Amazon product reviews (10 tables). Reward depends on using few exploratory queries (budget 15 per question); wrong answers score 0. A schema migration after question 20 causes drift. — [arXiv HTML](https://arxiv.org/html/2606.05661)
- Gain metric: g_t = r^stateful_t − r^stateless_t for the same system on the same instance. Normalized gain = (mean stateful − mean stateless)/(r_max − mean stateless), i.e. divided by headroom. Normalized reward uses a fixed external reference (stateless GPT-5.4 ICL). — [arXiv HTML](https://arxiv.org/html/2606.05661)
- Systems: full-context ICL, ICL Notepad, Mem0 (top-10 retrieval), ACE, Claude Code, and Codex. Models: Claude Opus 4.7, Claude Sonnet 4.6, Gemini 3.1 Pro, Gemini 3 Flash, and GPT-5.4. Claude Code and Codex use one persistent conversation per task with auto-compaction. — [arXiv HTML](https://arxiv.org/html/2606.05661)
- Results: the best system was ICL with Sonnet 4.6 (22.3% normalized reward, 25.4% normalized gain). ACE reached 8.6% gain at the highest cost ($62.8 mean rollout cost, against $30.4 for ICL Sonnet 4.6, $38.6 for Claude Code and $7.6 for Gemini 3 Flash ICL). Two Gemini 3.1 Pro configurations had negative normalized reward. — [arXiv HTML](https://arxiv.org/html/2606.05661)
- "naive ICL outperforms systems dedicated to memory management". "Accumulated state frequently hurts rather than helps", which the authors attribute to spurious generalizations, stale beliefs, over-reliance on recent instances, and rigidity in early wrong beliefs. — [arXiv abs](https://arxiv.org/abs/2606.05661); [arXiv HTML](https://arxiv.org/html/2606.05661)
- Rigor: each system gets 5 rollouts per task, in potentially different instance orders, with 95% CIs from per-task rollout variance (none for Codex because of resource limits). A stability-plasticity decomposition shows that some systems' gains come mostly from repeated exposure within a variant. — [arXiv HTML](https://arxiv.org/html/2606.05661)

### Inferences
- Anthropic's protocol (correct answer revealed, fresh session per question, file-directory memory, 30-question chart) does not exactly match the paper's Database Exploration description (feedback on incorrectness, 40 questions, migration after Q20, reward based on query economy). Anthropic likely ran a variant or subset. The 0.564 → 0.828 numbers are not directly comparable to the paper's normalized table.
- Codebase Adaptation nearly matches the requester's gap: hidden tests, conventions discoverable only by acting, a mid-stream repository switch, and a step-efficiency reward that still moves when every condition eventually solves the task. Because the harness is Apache-2.0 and pluggable, a memory layer can be dropped in as a `src/systems/` entry and compared against the same model's stateless run.

### Gaps
- The CL-Bench release post's body was not retrievable (header only). I could not confirm the exact Database Exploration feedback (whether the correct answer is revealed) or the Sales Prediction instance count.
- Anthropic does not publish its CL-Bench harness configuration, run counts or variance.

## 2. Coding-agent continual-learning benchmarks (same or different repositories; feedback; hidden conventions)

### Takeaway
Six coding-specific sequential or experience-reuse benchmarks appeared between mid-2025 and 2026. CL-Bench Codebase Adaptation (hidden regression tests, maintainer conventions, repo switch) and VibeMemBench (111 targets across 90 repos, executable tests, filtered so memory can matter, seeds and bootstrap CIs) are the most rigorous and directly adoptable. SWE-Bench-CL defines the right CL metrics but reports no real memory-on/off results. Across these benchmarks, off-the-shelf memory systems mostly fail to beat memory-off, and irrelevant or unfiltered memory measurably hurts.

### Cited Findings
- **CL-Bench Codebase Adaptation** (2026, preprint, Apache-2.0 harness): 19 issues from tablib and tenacity in blocked order. Hidden regression tests and "maintainer conventions" are part of the learnable latent structure. Reward is step efficiency. — [arXiv HTML 2606.05661](https://arxiv.org/html/2606.05661)
- **VibeMemBench** (arXiv 2609.23570, 20 Sep 2026, preprint, cs.SE): 111 SWE-style targets (bug fixes, features, interface and config changes) from 90 SWE-rebench V2 repos, plus 3,634 history trajectories. Executable tests decide resolution. — [arXiv abs](https://arxiv.org/abs/2609.23570)
  - Affiliations include SIAT-CAS and Alibaba. Memory systems tested: Mem0, SimpleMem, MemoryOS, and A-MEM. Solvers: deepseek-v4-pro, glm-5, glm-5.2, kimi-k2.7-code, and qwen3.8-max. Conditions: memory-off, frozen verified experience, an irrelevant-memory control (everyday sentences), and each memory system. — [arXiv HTML](https://arxiv.org/html/2609.23570)
  - Target filter (SIEVE): keep a target only if memory-off resolves it in fewer than 4/4 seeds and the best candidate memory improves the reference solver. The test patch is evaluator-only. — [arXiv HTML](https://arxiv.org/html/2609.23570)
  - Results (memory-off → frozen verified experience): deepseek-v4-pro 67.1 → 67.1; glm-5 55.0 → 57.4; glm-5.2 76.8 → 80.4; kimi-k2.7-code 69.8 → 74.3; qwen3.8-max 79.1 → 80.2. All five bootstrap CIs cross zero. Eleven of twelve solver-system pairings are at or below memory-off. Mem0 on glm-5 scored −5.5 points with an interval entirely below zero. The irrelevant-memory control scored −0.7 to −3.4. Losses concentrate where the solver already succeeds 4/4 without memory. Injection lowered agent steps for all five solvers. — [arXiv HTML](https://arxiv.org/html/2609.23570)
  - Rigor and cost: 4 seeds per target (444 target-seed runs); percentile bootstrap over targets with 10,000 resamples, seeds kept intact. Solver tokens and steps are reported; memory-side tokens, wall-clock time and API price are excluded. — [arXiv HTML](https://arxiv.org/html/2609.23570)
  - Release: github.com/AlibabaResearch/DAMO-ConvAI/tree/main/VibeMemBench (histories, executable predicate, intervention protocol). No code or data licence found; the paper is CC BY 4.0. — [arXiv HTML](https://arxiv.org/html/2609.23570)
- **SWE-Bench-CL** (Joshi, Chowdhury and Uysal, Columbia; arXiv 2507.00014, 13 Jun 2025; preprint): 273 SWE-Bench Verified tasks over 8 Python repos (django 50, sympy 50, sphinx 44, matplotlib 34, scikit-learn 32, astropy 22, xarray 22, pytest 19), ordered chronologically and then by estimated difficulty. Metrics: ACC, forgetting, forward transfer, backward transfer, AULC, tool-use efficiency, CL-F_β and a composite CL-Score. Memory is a FAISS index of attempt summaries. — [arXiv HTML](https://arxiv.org/html/2507.00014v1); [search summary](https://arxiv.org/pdf/2507.00014)
  - No memory-on/off results from the agentic framework; the authors call the planned experiments hypotheses. Preliminary standard-harness pass rates were below 8.5%, with memory "on par with or slightly worse". Code and data: github.com/thomasjoshi/agents-never-forget (licence not stated). — [arXiv HTML](https://arxiv.org/html/2507.00014v1)
- **SWE-ContextBench** (arXiv 2602.08316, v1 Feb, v3 May 2026; preprint): 1,100 base tasks and 376 related tasks linked by real issue and PR dependencies, across 51 repos and 9 languages. Metrics: resolution accuracy, runtime and token cost. Accurately summarized prior experience improves accuracy and lowers cost, especially on hard tasks; "unfiltered or incorrectly selected context" gives limited or negative benefit. The abstract gives no numbers and no data URL. — [arXiv abs](https://arxiv.org/abs/2602.08316)
- **Memory Transfer Learning in coding agents** (Kim et al., arXiv 2604.14004, Apr 2026; preprint): a unified memory pool across 6 heterogeneous coding benchmarks gives +3.7% average. Low-level traces cause negative transfer and high-level insights transfer ("abstraction dictates transferability"). Transfer scales with pool size and works across models. Project page: memorytransfer.github.io. — [arXiv abs](https://arxiv.org/abs/2604.14004)
- **AGENTbench / "Evaluating AGENTS.md"** (Gloaguen, Mündler-Sasahara, Müller, Raychev, Vechev; arXiv 2602.11988, v3 Sep 2026): repository context files "do not generally improve task success rates" and raise inference cost by over 20% on average. — [arXiv abs](https://arxiv.org/abs/2602.11988). Secondary sources say the benchmark is 138 Python tasks from 12 repos that ship developer-written context files, with LLM-generated files slightly lowering success and developer-written files giving about +4%. — [themoonlight review](https://www.themoonlight.io/review/evaluating-agentsmd-are-repository-level-context-files-helpful-for-coding-agents); [aiweekly](https://aiweekly.co/alerts/paper-finds-agentsmd-files-hurt-coding-agent-task-success). ICLR 2026 virtual-site listings exist, but the type of acceptance (main or workshop) is unverified. — [ICLR listing](https://iclr.cc/virtual/2026/10021235)
- **ReasoningBank** (Google and collaborators; arXiv 2509.25140; ICLR 2026 per secondary sources): memory distilled from the agent's self-judged successes and failures, without ground-truth labels. +4.6 points over memory-free agents on SWE-Bench-Verified, +8.3 on WebArena, and about 3 fewer steps per task. Adds memory-aware test-time scaling (MaTTS). — [Google Research blog](https://research.google/blog/reasoningbank-enabling-agents-to-learn-from-experience/); [arXiv HTML](https://arxiv.org/html/2509.25140v1)
- **SWE-Gym** (Pan et al., ICML 2025; earlier/foundation): 2,438 Python tasks from 11 repos with executable environments, built to train agents and verifiers (up to +19% absolute resolve rate). It is a training environment, not a CL or memory benchmark. — [arXiv](https://arxiv.org/abs/2412.21139); [ICML poster](https://icml.cc/virtual/2025/poster/46038)
- A 2026 survey, "Self-Evolving Coding Agents", warns that noisy logs, misleading tests, brittle patches and repo-specific conventions can produce memories that hurt future performance when retrieved uncritically. — [arXiv 2608.03392](https://arxiv.org/html/2608.03392v2) (from search snippet)
- RECODE-H (arXiv 2510.06186) is a research-code benchmark with interactive human feedback; I saw only its title and abstract snippet. — [arXiv](https://arxiv.org/pdf/2510.06186)

### Inferences
- Only CL-Bench Codebase Adaptation explicitly builds in conventions discoverable by failing (hidden regression tests plus maintainer conventions). VibeMemBench keeps tests evaluator-only but does not analyze conventions. None of the others targets "conventions learnable only by failing" as a design variable. A requester-built suite of hidden-convention checks (for example, a lint rule or a project-specific API contract checked only by a hidden test) would therefore be a novel contribution, not a reimplementation.
- The cross-benchmark pattern (VibeMemBench, CL-Bench, AGENTbench, SWE-ContextBench, SWE-Bench-CL preliminary) is that memory gains in coding are small (about 1 to 5 points) and often within noise, while off-the-shelf memory and irrelevant context often cost a few points. A gate that blocks unverified memory is well motivated, but a credible positive effect needs both a task filter and seeds.

### Gaps
- I found no benchmark named "SWE-bench sequences" or "repository-level continual learning" beyond those above, and did not verify EvoCodeBench (an evolving, contamination-resistant code-generation benchmark, not a CL or memory benchmark as far as I know).
- I found no released numbers for SWE-ContextBench or AGENTbench beyond the abstracts and secondary summaries.
- I found no coding benchmark with an explicit multi-session simulated user plus hidden project conventions plus drift. CL-Bench comes closest but has no simulated user.

## 3. Agent memory benchmarks: learning from feedback vs recall; knowledge updates, drift, forgetting, misleading or poisoned memory

### Takeaway
Most conversational memory benchmarks (LoCoMo, LongMemEval, MemBench, Mem-Gallery) test recall, and some also test knowledge updates or conflicts. They do not test learning from task feedback. The feedback-driven ones (StreamBench, Evo-Memory, MemoryBench, LifelongAgentBench, EvoMemBench, CL-Bench, DolphinBench) show memory can raise success when tasks are similar and feedback is reliable. Drift and conflict handling remains the weakest ability: at most 7% on MemoryAgentBench multi-hop conflict resolution, and about 60% correctness for GPT-5 on MEMTRACK. 2026 added dedicated poisoning benchmarks (MemSecBench, MPBench, MemPoison) that measure persistence, downstream consequences and repair.

### Cited Findings
**Feedback / test-time-learning benchmarks**
- **StreamBench** (earlier; NeurIPS 2024 Datasets & Benchmarks; Appier and NTU): an online stream with feedback from users, code execution or API responses. Streaming methods significantly beat non-streaming methods on most datasets. Code: github.com/stream-bench/stream-bench. — [NeurIPS proceedings](https://proceedings.neurips.cc/paper_files/paper/2024/hash/c189915371c4474fe9789be3728113fc-Abstract-Datasets_and_Benchmarks_Track.html)
- **Evo-Memory** (UIUC and Google DeepMind; arXiv 2511.20857, v2 May 2026; preprint): sequential task streams. Memory entries are built from input, output and feedback, where "Feedback f_t is considered the correctness signal". Datasets: MMLU-Pro, GPQA-Diamond, AIME-24/25, ToolBench, AlfWorld, BabyAI, ScienceWorld, PDDL. More than 10 memory modules, including Amem, Mem0, SelfRAG and Dynamic Cheatsheet, plus the ExpRAG baseline and the ReMem method. — [arXiv abs](https://arxiv.org/abs/2511.20857); [arXiv HTML v2](https://arxiv.org/html/2511.20857v2)
  - Multi-turn average success/progress, Baseline → ExpRAG → ReMem: Gemini 2.5 Flash 0.27/0.46 → 0.46/0.63 → 0.50/0.64; Claude 3.7 Sonnet 0.24/0.52 → 0.63/0.82 → 0.78/0.91. Single-turn average: Gemini 0.59 → 0.60 → 0.65; Claude 0.54 → 0.59 → 0.58. — [arXiv HTML v2](https://arxiv.org/html/2511.20857v2)
  - Storing both successful and failed experiences degrades the baseline methods. ReMem's gain correlates with within-dataset task similarity (Pearson r = 0.717 for Gemini, 0.563 for Claude). Baselines vary substantially between Easy→Hard and Hard→Easy order. One table inconsistency was noted. No run counts were reported. — [arXiv HTML v2](https://arxiv.org/html/2511.20857v2)
- **MemoryBench** (Tsinghua THUIR; ICML 2026, PMLR v306): an LLM-as-user simulator gives explicit and implicit feedback across languages, domains and task formats. Feedback-enabled systems beat vanilla baselines both off-policy and on-policy, but existing memory systems are "neither effective nor efficient enough" to learn continually from feedback. Code on GitHub; feedback logs at HF THUIR/MemoryBench. — [PMLR](https://proceedings.mlr.press/v306/ai26e.html); [arXiv](https://arxiv.org/pdf/2510.17281)
- **LifelongAgentBench** (Zheng et al., arXiv 2505.11942, May 2025): interdependent, skill-grounded tasks in Database, OS and Knowledge Graph environments with automatic label verification. Experience replay of up to 64 recent trajectories raised Database success from 19% to 78% for Llama-3.1-8B-Instruct, but plateaued or degraded in OS and KG because of context length and "reasoning noise". Venue not verified. — [arXiv](https://arxiv.org/pdf/2505.11942)
- **EvoMemBench** (arXiv 2605.18421, May 2026; listed as a NeurIPS 2026 poster): a 2×2 grid of in- or cross-episode × knowledge or execution memory, covering 15 memory methods against long-context baselines. Long-context baselines stay very competitive, memory helps most when context is insufficient or tasks are hard, and no memory form wins everywhere. Code: github.com/DSAIL-Memory/EvoMemBench. — [arXiv](https://arxiv.org/pdf/2605.18421); [NeurIPS 2026 listing](https://neurips.cc/virtual/2026/poster/139805)
- **DolphinBench** (Rathi, Yadav, Singh; arXiv 2609.24971, Sep 2026; preprint, 6 pages): memory is scored through task completion, with cost and latency reported alongside accuracy. 3 knowledge-work personas, each with about 500k tokens of messages and 200 tasks. Each task is verified to succeed with the relevant history and fail without it. Data and code at dolphinbench.ai. — [arXiv abs](https://arxiv.org/abs/2609.24971)
- **MemoryAgentBench** (Hu, Wang, McAuley, UCSD; arXiv 2507.05257): four competencies: accurate retrieval, test-time learning, long-range understanding, and conflict resolution. New datasets: EventQA and FactConsolidation. In multi-hop conflict resolution all methods score at most 7%. RAG wins on retrieval; long-context models win on test-time learning and long-range understanding. Code: github.com/HUST-AI-HYZ/MemoryAgentBench; data on HF. One review page says ICLR 2026, which I have not verified. Some sources call the fourth competency "selective forgetting". — [arXiv HTML](https://arxiv.org/html/2507.05257v1); [HF dataset](https://huggingface.co/datasets/Robin076/MemoryAgentBench/blob/main/README.md)
- **MEMTRACK** (Deshpande et al.; arXiv 2510.01353, Oct 2025; listed at a NeurIPS 2025 workshop): enterprise event timelines across Slack, Linear and Git that are noisy, conflicting and cross-referring, with codebase exploration. It probes memory acquisition, selection and conflict resolution, scored on Correctness, Efficiency and Redundancy. The best model, GPT-5, reached about 60% Correctness. — [arXiv](https://arxiv.org/abs/2510.01353v1); [NeurIPS 2025 listing](https://neurips.cc/virtual/2025/124523)

**Recall-centric conversational memory**
- **LongMemEval** (earlier; ICLR 2025; UCLA, Tencent AI Lab, UCSD): 500 questions on information extraction, multi-session reasoning, temporal reasoning, knowledge updates and abstention. LongMemEval_S is about 115k tokens per problem; LongMemEval_M has 500 sessions (about 1.5M tokens). Code and data: github.com/xiaowu0162/LongMemEval. — [ICLR proceedings](https://proceedings.iclr.cc/paper_files/paper/2025/file/d813d324dbf0598bbdc9c8e79740ed01-Paper-Conference.pdf); [arXiv](https://arxiv.org/abs/2410.10813v2)
- **LoCoMo** (earlier; ACL 2024; Snap): very long multi-session conversations (the ACL entry reports about 600 turns and 16K tokens on average, over up to 32 sessions) with QA, event summarization and multimodal generation. Long-context and RAG help but lag humans. Code: github.com/snap-research/locomo. — [ACL Anthology](https://aclanthology.org/2024.acl-long.747)
- **MemBench** (Tan et al.; ACL 2025 Findings): factual versus reflective memory, participation versus observation modes, including knowledge updating and temporal reasoning. Metrics cover effectiveness, efficiency and capacity. Code: github.com/import-myself/Membench. — [arXiv](https://arxiv.org/pdf/2506.21605); [ACL Anthology](https://preview.aclanthology.org/setup/2025.findings-acl.989)
- **Mem-Gallery** (Bei, Wei et al., UIUC; ACL 2026): multimodal multi-session memory scored on extraction and adaptation (including test-time learning), reasoning, and knowledge management of inconsistent or missing information. Simple multimodal RAG often beats structured memory, and storing everything hurts through cost and noise. Code: github.com/YuanchenBei/Mem-Gallery. — [arXiv HTML](https://arxiv.org/html/2601.03515); [ACL Anthology](https://aclanthology.org/2026.acl-long.1892.pdf)

**Misleading, wrong or poisoned memory**
- **Experience-following** (Xiong et al., arXiv 2505.16067; ACL 2026 per the Anthology preview): high input similarity to a retrieved record yields high output similarity, so stored errors propagate and can be amplified, and "similar but inherently misaligned records" hurt. Selective addition (checking quality before storing) plus deletion gives about a 10% absolute gain over naive memory growth. — [arXiv HTML](https://arxiv.org/html/2505.16067v2); [ACL preview](https://preview.aclanthology.org/ingest-acl/2026.acl-long.27/)
- **MemSecBench** (Chen et al., Zhejiang Univ. of Technology; arXiv 2607.27080, Jul 2026; venue unconfirmed): 310 cases from 48 contexts, including code. A Write–Execute–Forget protocol uses seven checkpoints (write occurred, malicious content persisted, recalled, influenced reasoning, external consequence, removed, benign memory preserved). 24 configurations: OpenClaw or Hermes harnesses × Native, Mem0, Mem0-Graph or A-MEM backends × 3 LLMs. Results: poison persisted in 84.2% of cases, recall 76.1%, adoption 53.7%, full Write→Execute chain 50.3%, removal 86.3% but benign memory fully preserved in only 62.5%, selective repair 56.1%. No code URL. — [alphaXiv](https://www.alphaxiv.org/abs/2607.27080)
- **MPBench** (Dash et al., arXiv 2606.04329, Jun 2026): a six-class memory-poisoning taxonomy tested on OpenClaw and HERMES. Average attack success is 50.46%, and existing prompt-injection defenses do not cover memory poisoning. — [arXiv](https://arxiv.org/abs/2606.04329) (abstract-level only)
- **MemPoison** (Gao et al., arXiv 2607.14651, Jul 2026): 1,227 hand-validated cases covering 4 attack types × 3 injection channels × 3 memory substrates. — [arXiv](https://arxiv.org/abs/2607.14651) (abstract-level only)
- An ICML 2026 paper, "From Untrusted Input to Trusted Memory: A Systematic Study of Memory Poisoning Attacks in LLM Agents", is listed. — [ICML 2026 listing](https://icml.cc/virtual/2026/67964) (contents not read)

### Inferences
- For a coding memory layer with a verification gate, the closest analogues for wrong-memory harm are: Evo-Memory's "store failures too" arm, VibeMemBench's irrelevant-memory control, CL-Bench's stale beliefs after a repo switch or schema migration, experience-following error propagation, and MemSecBench's persistence → adoption → repair funnel. MemSecBench's W/E/F checkpoint decomposition maps onto a gate's own stages (was a bad claim written, retrieved, acted on, repaired).
- Conflict and update handling is consistently the weakest axis. That supports evaluating a gate on drift scenarios rather than only on recall.

### Gaps
- PersistBench (Feb 2026) is mentioned only in a secondary article; I did not find its primary paper.
- The MemoryAgentBench and ReasoningBank venues (ICLR 2026) and MEMTRACK's affiliation are not confirmed from primary pages.

## 4. Evaluation design guidance: temporal splits, held-out projects, harm from wrong memory, runs and variance, cost

### Takeaway
The strongest recent designs share six features. (1) A within-system stateless baseline and a gain metric normalized by headroom (CL-Bench). (2) A task filter that guarantees memory can matter, meaning memory-off fails (VibeMemBench SIEVE, DolphinBench). (3) Explicit harm arms: irrelevant memory, stored failures, mid-stream drift, poisoning. (4) Several seeds and instance orders with paired, cluster-aware CIs. (5) Chronological or fresh-task splits against contamination. (6) Cost reported in tokens or USD next to success.

### Cited Findings
- **Within-system gain**: CL-Bench defines gain against the same system's stateless run on the same instance, normalizes by the remaining headroom, and separates stable learning from repeated exposure within a variant. — [arXiv HTML 2606.05661](https://arxiv.org/html/2606.05661)
- **Memory-necessary task filtering**: VibeMemBench keeps a target only if memory-off is below 4/4 seeds and a candidate memory improves a reference solver, then transfers the frozen experience to held-out solvers. — [arXiv HTML 2609.23570](https://arxiv.org/html/2609.23570). DolphinBench verifies each task by running the agent with and without the relevant history, requiring success with it and failure without it. — [arXiv 2609.24971](https://arxiv.org/abs/2609.24971)
- **Ceiling effect warning**: VibeMemBench finds memory hurts most where the solver already succeeds in all seeds without memory. — [arXiv HTML 2609.23570](https://arxiv.org/html/2609.23570)
- **Non-binary reward to escape the success ceiling**: CL-Bench scores coding by step efficiency (1 − (steps−1)/40) and database work by query economy. — [arXiv HTML 2606.05661](https://arxiv.org/html/2606.05661). VibeMemBench and ReasoningBank also report agent steps, and memory lowers steps even when resolution barely moves. — [arXiv HTML 2609.23570](https://arxiv.org/html/2609.23570); [Google blog](https://research.google/blog/reasoningbank-enabling-agents-to-learn-from-experience/)
- **Drift injection**: CL-Bench injects a repository switch (tablib → tenacity), a database migration after Q20, opponent changes and study shifts. — [arXiv HTML 2606.05661](https://arxiv.org/html/2606.05661)
- **Harm arms**: VibeMemBench's irrelevant-memory control costs 0.7–3.4 points. — [arXiv HTML 2609.23570](https://arxiv.org/html/2609.23570). Evo-Memory stores both failed and successful experiences. — [arXiv HTML 2511.20857v2](https://arxiv.org/html/2511.20857v2). Anthropic varied the memory-writing instruction (failure-only rule: −0.234 gain for Opus 5). — [Anthropic](https://www.anthropic.com/research/components-of-agent-memory). MemSecBench decomposes poisoning into persistence, recall, adoption, consequence and repair. — [alphaXiv 2607.27080](https://www.alphaxiv.org/abs/2607.27080)
- **Order effects**: CL-Bench uses 5 rollouts in potentially different orders. Evo-Memory compares Easy→Hard against Hard→Easy, where baselines vary substantially. — [arXiv HTML 2606.05661](https://arxiv.org/html/2606.05661); [arXiv HTML 2511.20857v2](https://arxiv.org/html/2511.20857v2)
- **Temporal splits**: SWE-Bench-CL orders tasks by creation time. — [arXiv HTML 2507.00014](https://arxiv.org/html/2507.00014v1). SWE-rebench (NeurIPS 2025 D&B) continuously mines fresh GitHub tasks and finds evidence of inflated SWE-bench Verified scores. — [NeurIPS 2025](https://papers.neurips.cc/paper_files/paper/2025/hash/21bec6ace947b1b58967b945c8ac0f10-Abstract-Datasets_and_Benchmarks_Track.html). SWE-bench-Live (arXiv 2505.23419) has 1,319 post-2024 tasks across 93 repos, each with a Docker image. — [arXiv](https://arxiv.org/abs/2505.23419v1)
- **Held-out projects and transfer**: Memory Transfer Learning measures cross-domain transfer and finds low-level traces transfer negatively. — [arXiv 2604.14004](https://arxiv.org/abs/2604.14004). VibeMemBench holds out solvers. — [arXiv HTML 2609.23570](https://arxiv.org/html/2609.23570)
- **Statistics** (earlier, Nov 2024; Anthropic-affiliated): report CLT standard errors, use cluster-adjusted SEs when questions share context (a task stream is a cluster), compare systems with question-level paired differences, and run power analysis before an experiment. — [Miller, Adding Error Bars to Evals](https://arxiv.org/pdf/2411.00640)
- **Seeds in practice**: CL-Bench uses 5 rollouts with 95% CIs. VibeMemBench uses 4 seeds with a target-level percentile bootstrap (10k resamples, seeds kept intact), and all frozen-experience CIs crossed zero. — [arXiv HTML 2606.05661](https://arxiv.org/html/2606.05661); [arXiv HTML 2609.23570](https://arxiv.org/html/2609.23570). HAL-based analysis notes agent sample sizes are modest (n = 13–38). — [Efficient Benchmarking of AI Agents](https://arxiv.org/pdf/2603.23749)
- **Cost accounting**: HAL (ICLR 2026) ran 21,730 rollouts across 9 models and 9 benchmarks for about $40k, and lists incomplete caching-cost accounting as a limitation. — [ICLR 2026](https://proceedings.iclr.cc/paper_files/paper/2026/hash/a0928f924a344aaebbb7f6cd8d56e34c-Abstract-Conference.html); [arXiv 2510.11977](https://arxiv.org/abs/2510.11977v1). CL-Bench reports mean USD per rollout. AGENTbench reports more than 20% higher inference cost from context files. SWE-ContextBench reports runtime and token cost. DolphinBench reports cost and latency. VibeMemBench omits memory-side tokens, a gap to avoid. — [CL-Bench](https://arxiv.org/html/2606.05661); [AGENTbench](https://arxiv.org/abs/2602.11988); [SWE-ContextBench](https://arxiv.org/abs/2602.08316); [DolphinBench](https://arxiv.org/abs/2609.24971); [VibeMemBench](https://arxiv.org/html/2609.23570)

### Inferences
Concrete recipe for the requester's prototype, combining the designs above:
- **Break the ceiling.** Score step efficiency or tool-call count (CL-Bench style) alongside pass/fail. Add hidden convention checks that fail unless a lesson from an earlier session is applied. Filter or construct sessions so the stateless run fails at least sometimes (the VibeMemBench and DolphinBench rule).
- **Add drift.** Change a convention mid-stream (a CL-Bench-style "migration") and measure stale-memory harm on the sessions after the change.
- **Add harm arms.** Include an irrelevant-memory control, a deliberately wrong or poisoned memory seed, and a "store unverified claims" arm without the gate. Report the MemSecBench-style funnel: written, retrieved, acted on, repaired.
- **Add a second project.** A blocked repo switch (CL-Bench) tests the multi-project setting cheaply.
- **Report statistics properly.** Report within-system gain against a stateless run, using paired per-session differences, clustered by stream, with at least 4–5 seeds and several stream orders.
- **Count all cost.** Include memory-side tokens (miner and gate calls), not just solver tokens.
- **Adopt vs imitate.** CL-Bench's harness is the most directly adoptable: Apache-2.0, Docker tasks, and a pluggable `src/systems/`. VibeMemBench's released histories and predicates are a second option, but their licence is unstated.

### Gaps
- I found no published guidance specific to the number of seeds for memory evaluations beyond the practices above, and no study of how many sessions per stream are needed to detect a given gain.
